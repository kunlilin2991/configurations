# CLAUDE.md

## Working Principles
- Do not assume unclear intent. If the goal is ambiguous, pause and ask.
- If the proposed approach is not optimal, explain why and suggest a better one.
- Prefer root-cause fixes over patches.
- Keep solutions simple and maintainable.

## Code Changes
- Understand the relevant code before making changes.
- Modify the smallest necessary surface area.
- Preserve existing style and architecture.
- Do not introduce new dependencies unless necessary.
- If a change is risky, explain the risk before proceeding.

## Output Style
- Be concise.
- Focus on information that affects decisions or implementation.
- Avoid unnecessary explanations.
